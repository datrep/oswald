# Fullstack Architecture Vision: Express + MSSQL

## 1. Backend & MSSQL Security Constraints
- **Pattern:** Controller -> Service -> Data Access Layer (DAL).
- **SQL Injection Prevention:** NEVER use string interpolation (`${}`) for SQL queries. All queries must use parameterized inputs via `mssql` npm package recordsets or prepared statements.
- **Connection Management:** Always leverage a centralized connection pool. Do not open/close raw pool connections inside routes.
- **Transactions:** Any multi-query mutation (inserting an order + updating stock) must explicitly use an isolated transaction block (`new mssql.Transaction(pool)`).

## 2. Express Routing & Error Standards
- **Routing:** Routes only map URLs to Controllers. No logic allowed in route definitions.
- **Controllers:** Controllers extract parameters (`req.params`, `req.body`), call Services, and handle HTTP responses.
- **Async Safety:** All async routes must be wrapped in a global `catchAsync` error handler or use middleware to forward errors to `next(err)`. Never use silent `try/catch` blocks that swallow errors.
- **Responses:** Standard JSend-style JSON formats: `{ status: "success", data: ... }` or `{ status: "error", message: ... }`.

## 3. Frontend to Backend Type Contract
- **DTI Alignment:** Database column names (PascalCase/snake_case) must be transformed at the DAL layer into camelCase before reaching the frontend to match frontend UI models perfectly.
