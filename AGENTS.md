# AGENTS.md — non-negotiable constraints

Read this before changing anything under `trading/`. It is deliberately short: it holds only what must survive a
session reset, not what a reader can discover from the code. Rationale lives in `docs/adr/ARCHITECTURE-DECISIONS.md`;
this file is the checklist.

---

## 1. Governing protocol for `trading/**`

Any change under `trading/**` or to policy settings requires, in this order:

1. add a feature entry to `trading/agent/epoch.js` (`FEATURES`) citing why the change and what it invalidates;
2. move `POLICY_FREEZE.at` to a timestamp **after** the edits land;
3. `node scripts/sync-feature-epochs.js --yes`;
4. `node trading/scripts/check-epoch-coverage.js` — it must print *"nothing unaccounted for after &lt;boundary&gt;"*;
5. `npm run test:unit`.

This is unconditional. A change without a boundary contaminates every forward measurement that spans it.

Two things about step 5 that are **not** derivable from the code, so they are stated here: the suite is otherwise
DB-free by design, and `test/constraint-ledger.integration.test.js` is the ONE file that talks to real SQL. On a
machine without the database it reports **skips, not failures**, and the skip names the reason — so `0 fail, N
skipped` is a legitimate result and must not be read as a broken run. Every other file stubs `db.getPool`.

## 2. One writer per fact

- The **bridge latch** (`paused`, `pausedSince`, `lastFailAt`, `pausedAlertAt`) is written only by
  `trading/plus500/health.js`. Everything else reads it.
- **Per-instrument facts** come from `trading/agent/instruments.js`. Do not build an inline symbol map.
- **Per-instrument policy** will come from `trading/agent/symbolPolicy.js` (not yet built). Until it exists, dials
  are global and must be read from `settings.risk`, not restated.
- Settings are owned, not shared. **The registry is `trading/store/ownership.js`, not this paragraph** — that file
  is authoritative, and if the two disagree this paragraph is the bug.
  - **Operator-owned**, never written by the machine: `risk.*`, `deliberation.*`, `budget.*`.
  - **Machine-owned**, never edited by hand: `bridge.*` runtime, `kill.initialEquity`, `watchlist.universe`,
    `watchlist.candidates`, `discovery.*`.
  - **Co-owned by ENTRY**: `watchlist.symbols` is ONE array carrying the operator's manual picks and the
    discoverer's `source: 'ai'` picks. A machine write may add, change or drop AI entries only; removing or
    mutating a manual entry is a violation. **Order is not ownership** — `[...manual, ...ai]` is rebuilt every cycle
    by `agent/discoverer.js`, so a rule that compared array positions would fire constantly with nothing lost.

## 3. One tab for Plus500

**Never open a second Plus500 tab.** The venue treats concurrent tabs as a session conflict and signs one out.
Measured 2026-10-26: a second tab produced a sign-out and a 4h45m entry block. Use
`require('trading/plus500/browser').newPage()` — it returns the *shared* tab — hold `pageLock` while you touch it,
and park back to `/open-positions` in a `finally`. Never `page.close()` it.

## 4. Ledgers are append-only and idempotent

Append-only is one rule. Idempotence is achieved three ways, and **the difference is who owns the guard** — so the
mechanism is per role, not one sentence for five tables:

- **Capture ledgers** — `NewsItems`, `CalendarEvents`, `AnalysesNotes`. The **writer** owns it: a deterministic hash
  and a `NOT EXISTS` guard, because re-capturing the same page must be a no-op.
- **`FeatureEpochs`** — `MERGE` on its natural key (`id`). Same property, different mechanism; the writer still owns
  it. Generated by `scripts/sync-feature-epochs.js`, never by hand.
- **`TradingEvents`** — an append-only **event log**, where repeats are legitimate (one boot event per boot, one audit
  per hour). It has **no writer-side guard by design**: the **caller owns dedupe**, so a new kind that must not
  repeat needs its own guard before it appends. `agent/constraintAudit.js` is the worked example — it dedupes on
  `tradeId` + `rulesVersion` before writing.

Never update a ledger row; corrections are new rows. A study may only use rows whose `capturedAt` is strictly before
the observation it judges.

⚠ Until 2026-10-27 this paragraph named all five tables and demanded "a deterministic hash and a `NOT EXISTS` guard"
from each. That was false for two of them, and the test that enforces it silently guarded only three. Do not
re-merge this list into one rule (§8).

## 5. Measurement rules

- `R` = move ÷ entry stop distance. Report both intra-bar orderings, never one.
- Matched nulls, not gut feel. Time-based out-of-sample splits, never random.
- Sample sizes in this repo are small: use exact tests for small n, ICC/DEFF for clustered data, and state the
  minimum detectable effect before claiming a difference.
- A result that survives one test has not survived. The wide-trail result measured +0.364R on 261 real entries and
  +0.003R on the full pool — it flipped sign between halves.

## 6. Numbers on a page are not facts

Every failure in this repository's history has the same shape: a value was computed correctly and never verified
where it landed. The trail engage typed the stop and then threw before `Update`. `pausedAt` recorded the last
failure while being read as the start. `grossPnl` on a mirrored row summed to 20× the account's real movement.
`publishedAt` was null on 824 of 824 rows because a query parameter excluded the engines that supply dates.

**Verify at the destination, not the source.** A builder test proves code and settings agree; it does not prove
the venue received the level.

### 6a. A number must state its unit **and** its population, or it is not a measurement

Two independent ways to be wrong, and every recent bad number in this repo was one of them:

- **UNIT** — what it measures. A round trip is not a spread. `roundTripBpsFromCfg` is
  `2 × (spread + slip) × 100`; its own comment states the decomposition and it was not read before a
  "6.76× spread error" was published. That ratio was the flat `0.05` slippage term.
- **POPULATION** — which rows, chosen how. Gold's p75 half-spread over 14 days is 0.0563; the venue's own
  ticket label at submit is 0.0098. Both `half_spread_pct_per_side`, both correct, 5.72× apart, because one
  includes overnight widening. A units-only guard does not catch this.

Use `trading/agent/measurement.js`. `claim()` builds a record, `compare()` refuses unless unit **and**
population match, `agreesWith()` is the separate named operation for a cross-population tolerance test, and
`render()` prints unit, population, n and window beside the number. Do not divide two cost figures inline.

## 7. When something is dead, say so in a way a reader can act on

A feed with no rows must distinguish *"the world was quiet"* from *"the pipe is broken"*. Every scheduled loop
records its failure reason in its own event kind. An absent measurement that is not named reads as a clean result.

## 8. Where the truth lives

**Code is authoritative for behaviour. Docs are authoritative for intent. Where they disagree, the doc is the bug.**

Three of these documents were wrong inside a single session: this file's ownership paragraph contradicted
`store/ownership.js`, the handoff said `InstrumentQuotes` gated per-symbol work when it did not, and a `store.js`
comment cited a sweep script that no longer existed. Adding documents does not reduce that — it relocates it.

So: **anything derivable from code must be generated from it, not restated by hand** — symbol lists, ownership
rules, epoch ranges, counts. A restated fact is a second producer of one fact, which is §2 one level up. Where a
document must state something underivable (why a decision was made, what was measured and by what method), it says
how to re-derive it and when it was last checked.
